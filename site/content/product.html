Keep structure honest

A CI gate that fails the PR when an edit makes structure worse

The gate runs the same regression verdict as codeweb_diff on each pull request. It builds the graph before and after the change.

The gate fails on a new dependency cycle, a new body-confirmed duplication, or a symbol that loses all callers. A change that only removes code passes.

No LLM is in the checks. A passing check does not prove the program works. Inspect unresolved analysis and run the relevant tests.

Use the package gate with --report-only during rollout. Findings retain their verdict; setup and analysis errors still fail.

name: codeweb gate
on: pull_request
jobs:
  gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: GhostlyGawd/codeweb/.github/actions/codeweb-gate@v0.16.0
        with:
          target: src
          codeweb-ref: v0.16.0
Principles

"My agent already has language-server lookups — why a map?"

LSP answers one hop, on demand

A language server is built for the editor loop: definitions, direct references, rename — one symbol, one hop, computed per request inside a live session. There is no whole-program artifact to diff, rank, or gate a pull request on.

codeweb answers the whole graph — and CI can gate on it

The map is one deterministic file: transitive impact ("what breaks two hops away"), duplication with body evidence, dead code, hotspots, and domain coupling. Agents query it over MCP; the CI gate diffs it to fail a structure-worsening PR.

The two compose — codeweb replaces the grep loop, not your language server.
